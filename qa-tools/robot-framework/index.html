How it is built

  • Page Object Model. Locators live in resource files per page; test files only call keywords.
  • Data-driven tests. Five valid users and six invalid login combinations run from one template rather than six copies.
  • Parallel by design. Each suite opens its own browser in Suite Setup and clears cookies and localStorage in Test Setup, so Pabot can run them together safely.
  • Robocop linting runs in CI before the tests, so style problems fail fast.
  • No driver management. Selenium Manager fetches the matching driver, so there is no ChromeDriver to pin.
