Test automation that runs itself

What the three have in common

  • Page Object Model everywhere. Selectors live in one place per page, so a UI change is a one-line fix rather than a sweep through the specs.
  • Tests are the documentation. BDD suites are written in Gherkin so a non-tester can read what is covered.
  • Nothing is submitted on production sites. Suites that point at live shops stop before checkout; only demo applications run destructive flows in CI.
  • Secrets never land in git. Credentials come from ignored env files locally and from repository secrets in CI.
  • Known bugs are tracked, not hidden. Defects the application ships on purpose are marked as expected failures rather than deleted.
