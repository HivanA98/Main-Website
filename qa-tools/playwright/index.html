Playwright · pytest 52 tests · 3 browsers · nightly

Playwright + pytest

One shop, tested three ways: through the interface, as complete purchase journeys, and directly over HTTP. Every push, pull request and nightly schedule runs the whole set on Chromium, Firefox and WebKit.

View on GitHub CI runs

What the 52 tests cover

Layer Covers Tests
UILogin, catalogue, sorting, product details, form validation and network behaviour26
End-to-endComplete shopping journeys across pages and user types12
Known bugsSaucedemo's deliberately broken users, marked as strict expected failures7
APIHTTP-level checks that bypass the interface entirely7

A green run reports 45 passed, 7 xfailed. The seven are bugs the application ships on purpose; recording them as expected failures means the suite goes red if one is ever fixed, instead of quietly passing.

How it is built

  • Page Object Model with reusable components, so a layout change touches one file.
  • Browser matrix in CI. The API job runs once; UI and end-to-end jobs fan out across Chromium, Firefox and WebKit.
  • Strict xfail for known defects, which turns a silent regression into a failing build.
  • Runs nightly as well as on push, so breakage caused by the application itself is caught without a commit.
